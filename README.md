# VITRANO — Твій світ покупок

Окремий україномовний онлайн-магазин. Проєкт не пов'язаний із MarketMix UA, Universal Marketplace UA або NORD.

## Ресурси
- GitHub: https://github.com/karinavurvihvost-max/vitrano
- Render: https://vitrano-storefront.onrender.com
- Render dashboard: https://dashboard.render.com/static/srv-dbcuj1qfngtc73b2v5s0

## Стан на зараз
- Адаптивна україномовна вітрина з пошуком, фільтрами, категоріями, картками товарів, деталями товару та кошиком.
- Демо-адмін-панель: локальне додавання, редагування, видалення товарів, фото-прев’ю, ціни, SKU, категорії та наявність.
- Корзина та обране зберігаються локально в браузері; кошик візуально розділяє товари за постачальниками.
- PWA-заготовка: manifest, SVG-іконка та service worker.
- Чернетка структури бази даних у `database/schema.sql`; схему не застосовано.
- Репозиторій публічний за рішенням власника.
- Окремий платний проєкт Supabase не створювали. Реальні замовлення та спільна база ще не підключені; магазин не готовий приймати реальні замовлення.

## Наступні етапи
1. Створити окремий Supabase-проєкт VITRANO лише після погодження вартості власником.
2. До запуску бази — перевірити всі функції демо-версії на телефоні та виправити помилки.
3. Переглянути RLS-політики: не відкривати публічно телефони, приватні нотатки та контакти постачальників.
4. Застосувати й перевірити схему та ролі адміністратора в окремому проєкті.
5. Підключити каталог і сховище фото.
6. Реалізувати серверне оформлення замовлення з перевіркою цін, наявності та одного постачальника на замовлення.
7. Реалізувати захищену адмін-панель для товарів, постачальників, замовлень, ТТН, відгуків і фінансів.
8. Перевірити на телефоні та пройти тестові сценарії перед запуском.

## Безпека
Не зберігати секретні ключі в публічному репозиторії. Не передавати в браузер Supabase service-role/secret key. Всі таблиці, доступні через API, повинні мати RLS та перевірені політики. Замовлення повинні створюватися серверною функцією з валідацією та захистом від спаму.
